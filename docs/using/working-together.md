# Work together without watching every step

Tell your agent what you want to achieve. A useful starting point is the result
you want to come back to: “a prototype I can try” is different from “a product
ready to release.” The agent helps turn that into a direction you can agree on.

## Keep one place to return to

The Goal holds the outcome. Its Brief shows the current plan or result. Larger
pieces can have their own Goals, so a discussion about one part does not bury
everything else.

Read the Brief and leave feedback on the relevant text or image, or write in
Conversation. Your feedback stays with that Goal. When the Brief changes, its
older versions and the discussion remain available.

You can also change direction from the agent chat. Ask it to keep the Web
explanation current so you do not have to reconstruct the chat later.

## Answer the questions that matter

A Letter is a question that needs your decision. Reply to the Letter when you
are ready. Other work within the agreement can continue while that question is
waiting. Answering does not mean that the entire project is finished.

Comments share information or results without asking for a reply. Look for the
agent's explanation of what changed and how it was checked, alongside the result
itself. A finished model run is not the same as an achieved Goal.

## Stay in control

The same header works on your phone and computer. **Goals** opens the project
list; **Agent** shows the current run. **More** groups AutoContinue, Notifications
and Public link, with a name and On/Off state beside each icon.

The Agent panel shows the current work and recent public updates, without a
list of old runs. Use Pause or Resume beside Activity to control supported work.
While manually paused, Auto mode sends no new continuation; Resume retains your
Auto mode preference.
The available controls depend on the connected harness and CLI version. Pausing
work and disabling [AutoContinue](auto-continue.md) serve different purposes:
one interrupts or holds work, while the other prevents future automatic checks.

Use **More** to set [notifications](notifications.md) or [phone access](public-link.md).
Each can be enabled independently; no separate setup skill is needed.
Local use needs neither.

The [core skill](../../plugins/chill-agent/skills/chill-agent/SKILL.md) guides the
agent's collaboration. Developers can find exact Goal and Letter behavior in
the [CLI workspace guides](https://github.com/game-dev-rta-club/chill-agent-cli/blob/main/docs/README.md).
