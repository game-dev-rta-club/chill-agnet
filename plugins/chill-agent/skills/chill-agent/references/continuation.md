# Respond to AutoContinue

The check describes observed activity and includes commands for reading the
workspace and returning a result. It is an opportunity to revisit the agreement,
not a new user request or permission to undo a pause.

Start with its short index query. Open relevant Goals to understand their
criteria, current Brief and discussion; follow printed history commands only as
needed. Saved states help locate work but do not prove the outcome was achieved.
Look for concrete unfinished work, a parent outcome still to verify, or a
necessary user decision that has not been sent as a Letter. Continue independent
work even when another branch awaits an answer. Avoid duplicate questions.

If every Goal is Done, check for a concrete omission in the agreed outcome.
Without one, leave the project at rest. Do not invent improvements or new Goals
to keep AutoContinue busy.

Record actual results or necessary questions through the usual Web workflow.
Then use the incoming monitor result command exactly as supplied, with outcome
`worked` if you advanced work or left a necessary Letter. Use `no-work` if there
is nothing to advance. A no-work result belongs only on that internal route:
do not post a no-work Comment, Letter or Brief edit. Ordinary user feedback
still receives its normal response.

The result command records this attempt; it does not end the turn itself. If
it fails or is unavailable, do not claim it was saved or substitute a no-work
Web post. Preserve the error for the caller. Monitoring and delivery are handled
by the runtime; do not start another loop to compensate.
