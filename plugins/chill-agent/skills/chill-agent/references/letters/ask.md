# Ask through a Letter

Use this before deciding to interrupt the user. The useful result may be a
Letter or a decision you can make yourself.

Investigate facts you can obtain, use existing preferences and exercise the
judgment already entrusted to you. A reversible draft is often better than
asking about every detail. Ask when a consequential choice belongs to the user,
changes the agreed destination, or needs authorization not already present.

Check existing Letters and their discussion so the same question is not asked
again. Prepare enough authorized work for the user to judge something concrete.
For example, finish and check an agreed private preview before requesting a
public release that still needs permission.

Use `goal letter --help`. Give it a short decision title and explain what the
choice changes, your recommendation, and what you can advance before an answer.
Separate the part that must wait from independent work; do not imply that
silence permits an action requiring approval. Ordinary information and usable
outcomes belong in Comments; follow
[reporting](../comments/report.md).

Save the Letter in the Web so it remains available whenever the user returns.
Chat-only question tools do not save it; use those only when the user explicitly
asks to answer there. Handle any configured notification through
[delivery](../notifications/deliver.md), then continue independent agreed work.
