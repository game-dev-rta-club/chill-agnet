# Review result delivery

Use this in AutoContinue's stopping review or when a completed request may have
ended with only a Comment. Compare the original request, actual outcome and
recent Conversation, including Letters that were answered or closed. Open-Letter
counts and Goal completion labels alone cannot show whether it was delivered.

Find the concrete result the user asked to receive. If it exists but only in a
Comment or chat, and the user has not requested that channel, save a concise
Letter with the result, its useful link, evidence and any important limitation.
Use [Report a result](report.md) and the configured notification guide. This
repairs the handoff; do it now instead of listing it as future work. For example,
a requested performance investigation can be finished while its conclusion
still needs to be brought to the user's attention.

First check whether a Letter already covers that outcome. Reuse its saved event
for any genuinely outstanding notification step; never create another merely
because it is unread, closed, unanswered, or notifications are Off. Do not
reconstruct or retry an uncertain send. Recover the current missing handoff,
not every old Comment in the project. Routine progress, no new outcome, and
already delivered results do not warrant another Letter.

A result Letter need not contain a question. Do not make the user's reply a new
completion criterion or stop other authorized work. A missing substantive result
still calls for work within the agreement, not an announcement that it is done.
If the requested task was investigation only, delivery does not authorize the
suggested implementation. If the result is delivered and no agreed work remains,
finish the pass without inventing work. Record a recovered handoff as `worked`;
otherwise use the supplied no-work receipt when appropriate.
