# Complete a Goal

Use this at a stopping point to decide whether the shared destination is real
for the user. Leave either a supported completion or a concrete remaining gap.

Compare the result with the Goal's criteria and current agreement. What can the
user now do, and what evidence supports it? Check the actual result where
possible. Distinguish what was verified from what still depends on external
conditions or the user's experience.

A completed design can advance a broader outcome without finishing it. It also
does not authorize implementation outside the current scope. Conversely, do not
keep an achieved Goal open merely because more improvements could be imagined,
or require a new approval for a result already within the agreement.

Record the result and relevant evidence in the Brief and deliver the outcome
using [Report a result](../comments/report.md). All
descendants must be Done before `goal update` can mark this Goal Done. Review
ancestors against their own criteria; child completion is not parent completion.

A stopped run, answered Letter or saved Comment does not establish success.
If work remains, identify the missing outcome and advance what is authorized;
record Waiting only where progress really depends on something unavailable.
Answer informational follow-ups on a Done Goal without reopening it. Reopen it
for newly agreed work or an actual omission, then select that work explicitly.
