keyPoints: >-
  Group Goals by contributing outcomes, preserve their discussion and state,
  and keep a change of approach distinct from a change of destination.
---

# Reorganize Goals

Use this when the current hierarchy no longer helps someone find the work or
understand its contribution. Aim for a short, useful map of outcomes.

Read the relevant `goal review` index, then the scope, criteria and discussion
of the Goals affected. Update an approach in the scope or Brief when the
outcome is unchanged. If the destination itself needs to change, make that
change explicit using the user's feedback or an appropriate discussion.

Group related outcomes under a meaningful parent. Split a branch when it has
its own result, decisions or independent progress—not for each implementation
step. A parent describes the result its children contribute to, not merely a
folder called “Tasks.”

Use the supported metadata and parent updates from `goal update --help`.
Preserve IDs, historical Briefs and discussion when regrouping; do not delete
history to make an index shorter. Existing waiting reasons and pauses still
apply. Review the affected ancestors' criteria and current explanation after
moving children. The new structure should make the destination easier to see,
not imply that regrouping achieved it.
